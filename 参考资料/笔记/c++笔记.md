IR 是编译器内部的一种中间表示形式，用于在语义分析之后、目标代码生成之前承载程序的结构和数据流。它通常采用 SSA 形式，去除了 C++ 语法层概念，将程序降级为 load/store/call 等基础操作，是优化发生的核心层。



C++ 的内存模型是对程序中对象存储、生命周期以及多线程可见性规则的抽象。
 单线程下由 as-if rule 约束优化边界；
 多线程下通过 happens-before 和 atomic memory order 定义可见性与顺序保证；
 如果发生 data race，行为是 undefined behavior。

C++ 的内存模型本质上是一个“优化契约模型”：
 单线程通过 as-if rule 允许激进优化；
 多线程通过 happens-before 限定可见性；
 一旦违反规则（UB 或 data race），编译器不再保证行为。



C++ Lambda 本质是编译器生成的匿名类对象，捕获的变量成为成员变量，函数体变成 operator()。如果没有捕获，可以转换为函数指针。Lambda 是一种闭包，因为它将函数逻辑和其捕获的外部环境绑定在一起。使用时需要注意生命周期问题、引用捕获悬空、并发下的数据竞争，以及 mutable 对捕获副本的影响。

unique_ptr 是独占所有权的智能指针，通过移动语义转移所有权；shared_ptr 通过控制块中的原子引用计数实现共享所有权；weak_ptr 不拥有对象，仅引用控制块，用于解决循环引用。shared_ptr 的计数是线程安全的，但对象访问本身不是线程安全。make_shared 优化了内存布局，提高缓存局部性。



#### 2.1 设计原则（SOLID + 其他）

- **单一职责（SRP）**：一个类只做一件事。
- **开放封闭（OCP）**：对扩展开放、对修改封闭（用抽象/多态）。
- **里氏替换（LSP）**：子类可完全替代父类。
- **依赖倒置（DIP）**：依赖抽象而非具体。
- **接口隔离（ISP）**：客户端不依赖不需要的接口。
- **迪米特法则**：只与直接朋友说话。



####  C++ 特有架构 idiom

- **RAII**：资源获取即初始化（构造函数申请，析构函数释放）。智能指针、锁守卫都是 RAII。
- PIMPL（Pointer to Implementation）：隐藏实现，减少编译依赖。
  - 示例：class Widget { class Impl; std::unique_ptr<Impl> pImpl; };
- **CRTP（奇异递归模板）**：静态多态。
- **类型擦除**：std::any / std::function 实现。





#### 死锁

- 四个必要条件：互斥、占有并请求、不可抢占、循环等待。
- 预防：破坏其中一个（按序申请资源）。
- 避免：银行家算法。
- 检测：资源分配图找环。
- 解除：终止进程或抢占资源。

#### 内存管理 & 虚拟内存

- 分段 + 分页。
- 页面置换算法：FIFO、LRU、OPT。
- 缺页中断 → 换入换出。
- 虚拟内存优点：进程隔离、内存扩充。

#### IPC（进程间通信）

- 管道、消息队列、共享内存（最快）、信号量、socket。



#### C++ 并发库（<thread> <mutex> <atomic> 等）

- **std::thread**：创建线程；join/detach。
- **mutex**：互斥锁；std::lock_guard / std::unique_lock（RAII）。
- **condition_variable**：生产者-消费者经典（wait + notify）。
- **atomic**：无锁编程；memory_order（seq_cst 最强、relaxed 最弱）。
- **future / promise / async**：异步返回值。
- **thread_local**：线程局部存储。
- **std::shared_mutex**（C++17）：读写锁。

## 互斥锁 vs 自旋锁

互斥锁：

- 会陷入内核
- 上下文切换

自旋锁：

- 不进入内核
- CPU 忙等

适用场景：

- 锁时间 < 上下文切换时间 → 自旋锁
- 否则 → 互斥锁

#### 锁与同步

- 死锁预防：统一加锁顺序、超时、try_lock。
- 自旋锁：短临界区用（std::atomic_flag）。
- 读写锁：读多写少场景。
- 无锁数据结构：CAS（compare_exchange）。
